# Demo 终局结算兼容修复

2026-11-01，兼容补丁 revision 5。

## 原因与边界

`cl_demo_predict 0` 下，删除 `cs_win_panel_match` 仍不足以阻止结算。当前 CS2 客户端的比赛规则实体会在 `m_gamePhase` 变化时生成本地 `game_phase_changed`；阶段进入 `5` 时，结算监听器还有一条独立的显示路径。删除 Demo 中的 GameEvent 不会删除这项实体状态。

这是通过客户端静态分析、同文件对照及实机复测得到的结论。此前手工删除事件后的 Demo 与 Insight 缓存逐字节一致，本次样本的差异来自播放参数触发的另一条结算路径。保留 `cl_demo_predict 0`，以兼容需要关闭预测的 Demo。

## 实现

共享兼容预检先处理旧消息 138、终局事件及既有未完成 Demo 恢复，再调用独立 `demo-terminal-phase` 工具：

- 根据 Demo 序列化类名 `*CSGameRulesProxy` 和字段名 `m_gamePhase` 识别目标，不使用客户端内存偏移。
- 只把阶段 `5` 改为 `3`，且必须先在同一 Demo 的更早 tick 观察到正常阶段 `3`。只有终局片段、未识别编码等输入会明确失败，不猜测阶段。
- 通过 writer 的原始字段回调覆盖增量实体包、所有完整快照（包括顺序解析不作为锚点的快照）和实例基线；保留字段整数编码。
- 完整重扫输出，要求终局字段数为零、总字段数不变，其他阶段计数不变；同时核对所有外层命令和 tick、Demo 元数据及头部索引。
- 工具返回源/目标 SHA-256 与计数。Python 再验证回执、源文件未变及输出哈希，才替换候选。

事件清理和实体阶段改写在临时副本中一起完成，再原子发布到输入路径；任何步骤失败均不替换输入、不缓存成功。换肤兼容基线继续保留图库原件不变。补丁 revision 4 的成功缓存和 `.skin-compat-v4-*` 基线不会被当作新版兼容结果复用；新版缺少实体检查回执也不能命中成功缓存。

这是从 Pro 同步到 Free 的共享离线处理，不依赖 HLAE、原生注入或 Pro 授权；Free 保留 OBS 录制路径。两个 Windows 打包入口均需包含 `demo-terminal-phase.exe`；缺少工具会报错，不能跳过检查。

## 手工回归

1. 构建 `tools/demo-cosmetic-rewriter` 的 `demo-terminal-phase`；开发环境放在其 `target/release` 下，正式安装由打包脚本放入 `tools/`。
2. 将一份未修改样本交给共享 `ensure_demo_compatible`，检查修复报告中 `terminal_phase_checked=true`、`remaining_terminal_phase_fields=0`。第二次预检应命中 revision 5 缓存。
3. 保持 `cl_demo_predict 0` 播放到最后回合结束，检查不显示结算，再向前回跳；另外从末段快照跳入，确认结算没有恢复。
4. 在 Free 中用 OBS 录制包含最后回合的任务，检查收尾、跳转与录制完成，并检查高级播放。保留 Free 的 OBS-only 录制行为。
5. 测试旧兼容缓存、换肤基线更新及缺少工具/工具校验失败，检查不会把未经新版处理的文件报告为兼容成功。
